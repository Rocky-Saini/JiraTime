📖 How to use JiraTime

JiraTime fills your Jira worklogs for many days at once, logs your normal day automatically, keeps Issue fields (estimate, dev dates, AI usage) up to date, and syncs the NewersWorld timesheet.

1 · Getting started

  1. Create a Jira API token: id.atlassian.com → Security → API tokens → Create API token. Copy it.
  2. Open JiraTime and click Connect Jira (or follow the setup wizard). Enter your site (e.g. https://yourcompany.atlassian.net), your Atlassian email and the token.
  3. Tick Remember on this device if you want the daily auto-log. Without it the token is forgotten when you close the tab.
  4. The setup wizard then asks what work you do, which Jira issue each one goes to, builds your normal day (e.g. 8h) and turns on the auto-log.

Your token stays in this browser only. It is sent with each request to the JiraTime proxy, which passes it to Jira and does not store it.

2 · Calendar & bulk fill

  • Colours: complete (8h) · partial · missing (past working day, nothing logged) · striped = holiday / leave · blue = selected.
  • Hover a day to see every Jira issue and the hours logged on it.
  • Dashboard numbers: Working days = Mon–Fri minus holidays/leave. Completed = working days with ≥ 8h, Partial = some time but < 8h, Pending = no worklog yet (missed before today + upcoming). Total logged = everything this month on any day (time on holidays/weekends is shown separately). Remaining = for each working day, 8h minus what is logged that day, added up — e.g. 6 pending days and nothing partial = 48h. AI efficiency = Σ AI Time Saved ÷ Σ Original estimate for the issues you logged work on this month; click it to open the report.
  • Select days: click a day, drag across days for a range, or use Select all working days / Select missing days. Saturday and Sunday are skipped unless you allow them in Settings.
  • What to log: pick an issue in a row (type the key or words from the summary), set hours (1h–8h buttons or e.g. 1h 30m) and a comment. Add more rows for more issues, or load a template / day plan.
  • Preview & submit: shows every entry before anything is sent. Days that already have work on the same issue are unticked (skip existing). Entries on the same day get start times one after the other (10:00, 12:00 …). Tick Dry run to test without sending.
  • ⚡ Fill my month: selects every missing working day up to today and fills it with the rows, or with the day plan for that weekday.
  • ⚖ Balance partial days: tops up days that have less than your daily target.
  • Failed entries can be retried; history keeps every batch so it can be undone.

3 · Day details: edit, move, delete

Click ⋯ on any day (or Open day on the Today card).

  • Change hours or comment of a worklog, then Save.
  • Move to another date: change the Date of the row (e.g. 20 → 21), the button becomes Move. The time of day is kept. You are warned if the new day is a weekend, a holiday, in the future, or would go over your daily target.
  • 🗑 Delete removes the worklog from Jira (asks first).
  • Add work to that day with a day plan or a single template.

If Jira has locked the period (e.g. a closed timesheet), Jira refuses the change and the message is shown.

4 · Quick log

Type in the ⚡ box at the top of Worklog configuration and press Enter. A preview opens before anything is sent. If you write no date, the days selected on the calendar are used, otherwise today.

5 · Templates & day plans

  • A template is one kind of work: name + Jira issue + hours + comment + quick-log words. 15 starters are included (DSM, sprint ceremonies, AWS SR, AWS Connect, Lambda/API, deployment, unit testing, SIT/UAT, bug fixing, code review, production support, requirements, documentation, POC). A template with an orange border still needs its Jira issue.
  • A day plan is your normal day, e.g. DSM 30m + AWS Connect 5h 30m + Unit testing 2h. The badge shows the total against your target.
  • Mark weekdays on a plan to make it the default for those days (Fill my month, Today card, auto-log). Each weekday belongs to one plan, e.g. a “Monday” plan with sprint planning.
  • On the calendar: ＋ From template… adds a row, Save row as template, Day plan… loads a plan into the rows, Save as day plan saves the current rows.
  • ⬇ Export / ⬆ Import shares templates and plans with your team as a JSON file (weekdays are not imported).

6 · Daily auto-log & reminder

  • Turn on Log my day plan automatically, choose the time (e.g. 18:30) and the days.
  • At that time a countdown (60 s) shows what will be logged; press Cancel to skip today, or choose Ask me first.
  • It never adds to a day that already has work, and skips weekends, holidays and leave.
  • If JiraTime was closed at that time, it offers the missed days next time you open it.
  • It runs only while a JiraTime tab is open. Keep it as a pinned tab, and in Chrome add the site under Settings → Performance → Memory saver → Always keep these sites active.
  • Evening reminder: a desktop notification if today is not complete.
  • Dry run for today shows what would be logged; the run log lists every run.

7 · Weekly grid

Issues × days for one week. Grey numbers are already logged in Jira; type hours in a cell (e.g. 2, 1.5h, 90m) to add more. Copy last week pre-fills from last week's worklogs. Review & submit opens the same preview as the calendar.

8 · Issue fields

  • Search an issue and edit Original estimate (e.g. 1w 2d 4h), Actual Dev Start/End Date, AI Used / AI Tool Used / AI Time Saved and any other editable field. Fields that already have a value are shown automatically.
  • 📅 Dev dates from my worklogs sets Actual Dev Start/End to your first and last worklog on the issue.
  • Presets save a set of values (e.g. “AI used – Kiro”) to apply in one click; Apply to other issues… copies your changes to other issues.
  • The Time tracking box shows logged vs estimate and the live AI efficiency while you type.
  • Only the fields you change are sent, after a confirmation that lists old → new values.

9 · AI efficiency

AI efficiency = (AI Time Saved – Development + Testing + Documentation) ÷ Original estimate. Example: estimate 16h, AI saved 2h → 12.5%.

  • below 10% too low — highlighted, aim for at least 10%.
  • 10–20% on target (green).
  • 20–40% high — allowed, check it is realistic.
  • above 40% over the maximum — highlighted.
  • No estimate — set the Original estimate first.

Choose which issues to check (this month, last month, last 3 months, or your open issues). Click a coloured box to filter. For red/orange rows, Set dev … → 15% opens Issue fields with the value that brings the issue to the middle of the green band; review it and press Save. The limits (10 / 20 / 40) can be changed on the page. Export CSV gives the full report.

10 · NewersWorld sync

  1. Open 🏢 NewersWorld Timesheet and drag the ⭐ JiraTime Agent link to your bookmarks bar (once).
  2. Click ↗ Open NewersWorld (you are already logged in there) and click the bookmark in that tab. The badge turns green.
  3. Read NewersWorld & compare shows each day: will fill, already in sync, different, leave, locked. Leave dates are marked on the calendar.
  4. Sync till today fills the empty days from your Jira worklogs (filled, leave and locked days are left alone unless you allow overwrite).

If the bookmark was created on another address (e.g. localhost), delete it and drag it again from this page.

11 · History, undo & reports

  • History & Undo: every entry JiraTime sent, edited or moved. Undo batch deletes a whole submission from Jira; Export CSV keeps a record.
  • Reports: hours per day, per issue, per project and per week for the month on the calendar, a printable timesheet (PDF) and CSV.

12 · Settings & holidays

  • Daily target hours (default 8), default duration and start time, delay between requests, allow weekends.
  • Holidays & leave: add single dates or ranges; they are skipped everywhere and shown striped on the calendar.
  • Remove saved credentials deletes the token and all saved Jira data from this browser — use it on shared computers.

14 · GitLab workspace

A separate workspace for your GitLab, with its own connection. Your browser talks to your GitLab directly, so the VPN must be on. Working with folders on your laptop (clone into a folder, commit, push, conflicts) uses the JiraTime helper, which you set up once from GitLab → Local repos.

  1. Create a Personal Access Token in GitLab (avatar → Edit profile → Access tokens). read_api is enough to look around; for merge requests, approvals, retries and push you need api + write_repository.
  2. Open 🦊 GitLab Workspace (bottom of the sidebar, or the 🦊 pill in the top bar), enter the GitLab URL, your username and the token, and press Connect.
  3. Overview: projects, active projects, open / assigned MRs, pending reviews, failed pipelines and your pushes of the last 7 days, plus the projects you worked on most recently.
  4. Projects: search, filter, ★ pin. Click a project for branches, commits (click one for its diff), MRs, pipelines and contributors, and ⬇ Clone it into a folder you pick.
  5. Local repos: repositories on this laptop. Changes with a diff viewer (stage / unstage / discard per file or per hunk), commit with templates and a suggested message, push, pull, fetch, history with a branch graph, branches (create, switch, merge, rebase, compare, delete), stashes, revert, tag, reset. Discard and hard reset keep a backup first; JiraTime never force-pushes.
  6. Conflicts: after a merge, pull or rebase with conflicts, each conflict is shown side by side — accept current, incoming, both, or edit by hand — then Mark resolved and Continue (or Abort).
  7. Merge requests: created by you, assigned, review requested, or per project. Open one for overview, changes (with a rule-based smart review), commits, discussion and pipelines; approve, comment, edit, assign, label, draft / ready, close and merge. ＋ New merge request / 🔀 Prepare MR compares the branches and drafts the title and description from your commits.
  8. Releases: what changed after a date across many projects — commits, merged MRs and deployments are kept apart — by project, by developer, as a timeline, files changed since the release, CSV and an RCA draft. Compare does tag vs tag, branch, SHA or two dates, with release notes, CSV and print.
  9. Pipelines: jobs by stage, job logs with search and “first error”, retry a job or the failed jobs (asks first), environments and deployments. Activity: your or a project's GitLab timeline. Jira links: merge requests, branches and commits for a Jira key, and start a branch for it.
  10. Ctrl + K anywhere opens a search for pages, projects, repositories, merge requests and actions; type a Jira key to look it up in GitLab.

The token is checked with GitLab and stored only on this laptop (OS keyring, or ~/.config/jiratime/gitlab-token readable only by you). The browser never receives it; git gets it only for the single command it runs. “Smart summary / review” and the RCA draft are rule-based: nothing is sent to an AI service.

13 · Problems & answers

“Could not reach Jira (…)” / 502
JiraTime could not connect to Jira (network, VPN or slow DNS). Press Retry next to the message. The first request after starting can take ~8 s on some office networks.
“showing saved data · updating…”
The calendar shows the last data saved in this browser while fresh data loads. If loading fails, the error appears in red with a Retry button.
“Jira rejected the credentials”
The API token is wrong or was revoked. Settings → Change Jira account / token.
Jira refuses to edit, move or delete a worklog
The period may be locked in Jira/Clockwork or you lack permission; the message from Jira is shown.
The auto-log did not run
The JiraTime tab was closed or asleep at that time. Open it — missed days are offered. Check the run log on the Automation page.
NewersWorld says “not connected”
Open NewersWorld with the button on this page and click the bookmark in that tab. Re-create the bookmark if you moved JiraTime to a new address.
